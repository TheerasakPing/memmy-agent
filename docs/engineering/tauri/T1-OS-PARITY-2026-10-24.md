## Implemented for the Rust/Tauri shell

- Notifications via Tauri OS notification plugin: task done and update available.
- Launch-at-login using Tauri native autostart (read, enable, disable).
- Stable native installation UUID persisted under app-local data with basic symlink/corruption regression test.
- Native project and empty-project directory picker, preserving the original `{canceled,path}` contract.
- Tauri window resize emits fullscreen state to the existing React fullscreen listener. The listener also unsubscribes correctly.
- Stronger positive and negative React-to-Rust IPC contract tests; no fake successful fallback.
- Existing Electron preload untouched. Debug `.app` and GUI API tests are separate from installer evidence.

## Still blocked (release P0)

- 69 bridge methods; Pet Mode, tray, embedded browser and Computer Use must match old behavior.
- Existing notification/autostart/picker commands are not native E2E-certified, even though their mocks and compilation pass.
- Rust-owned secure Agent/Memory backend lifecycle and old user-data import/rollback not yet implemented.
- Signed Tauri installers and full UI screenshot parity on macOS arm64, Windows 11 x64, Linux.
- Scoped multi-tenant R1/R2 Security work requires independent approval and integration from PR #27.
- GitHub Actions workflow dispatch HTTP 422 is tracked in issue #26.
- Current `csp: null` must be hardened and independently reviewed before release.

**Rollback:** Do not replace the existing Electron production build yet. PR #30 is isolated and stack-revertible; it changes no existing user data.

## Lead review notes

- Rust's `std::env::consts::OS` uses `macos`/`windows`, but the original React DTO expects `darwin`/`win32`. A platform mapping is now verified by a Rust unit test; this is source-contract parity only, not OS screenshot parity.
- No live notification delivery, launch agent changes, native folder selection or access permissions were approved by independent QA. Keep PR #30 Draft.
