# Windows 11 x64 / Tauri v2 NSIS Developer Preview build — build checklist

## Scope and acceptance

Goal: produce a genuine **Windows x64 Tauri v2 NSIS `.exe`** built with `x86_64-pc-windows-msvc` toolchain on Microsoft Windows-hosted GitHub Actions, retaining the original 14 React routes, original controls/labels and embedded Node 26 Memory, Local API, Agent Gateway with locally built Windows SQLite addon. Unsigned preview only. Windows Server 2025 CI runner builds the Win11-compatible binary; **Windows 11 desktop GUI/installer acceptance requires actual Windows 11 machine**.

## A1 source audit / planner

- [x] A1: Previous portable bundled Runtime staging supported macOS arm64 only and copied Mach-O `node`; Rust `runtime_paths()` and `select_native_runtime_root()` required `node` even under Windows. Windows could not start bundled native Memory sidecar.
- [x] A2: Rust compiled Windows runtime now requires `runtime/node.exe` and Windows installed binary locates `runtime/` next to the NSIS-installed app executable, not macOS `Contents/Resources/runtime`.
- [x] A3: Existing React UI/14 routes and 84/85 bridge count stay unchanged; Tauri bundle keeps original MV3 Browser Extension.
- [x] A4: Native runtime stage fails on wrong host CPU/OS, unexpected pinned Node version, symlink/junction source path escapes, missing compiled Agent-private dependencies and wrong-platform SQLite native addon. `node.exe` comes from actual Windows x64 runner, not Homebrew or downloaded unverified random binaries.
- [x] A5: Windows x64 Tauri NSIS CI is in existing tauri-v2-parity.yml. Job runs on explicit dispatch OR exactly this Windows-preview PR branch, not other unrelated PRs. It uploads actual NSIS EXE plus SHA-256 manifest, and requires compiled Windows Node 26, real native SQLite/Memory CLI, Rust MSVC check, silent NSIS install and Rust-owned Memory/Agent start/stop.
- [ ] A5: Windows Actions runner check `cargo check --locked`, real Windows Node GYP rebuild, stage runtime, React production compile, NSIS executable build. Attach GitHub run ID and actual downloaded installer after results.
- [ ] A5: Even a Windows Server 2025 CI-installed NSIS preview is not a Windows 11 desktop GUI test. WebView2/installer UX, SmartScreen, icons/Menu, Browser Extension and uninstall/rollback require real Windows 11 x64 GUI acceptance.
- [ ] A4: Windows Defender SmartScreen/Authenticode signing still not provisioned; unsigned installer **will trigger warnings**. Never instruct disabling Defender or changing OS security policies globally. Valid signed production release requires trusted publisher certificate and independent security review.
- [ ] LEAD: 1 original Electron native method unported (`dragBrowserExtension`), 5 behavior-partial (Updater trio; native tab mention; selective Browser data clearing), native WebKit/Agent browser session split. `releaseReady=false` until Windows 11 GUI E2E and all release gates.
